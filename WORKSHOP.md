# Workshop: your first AI assisted website

## Goal

Customize a working Astro blog, save it to your own GitHub repository, deploy it, and verify one visible change. Keep your repository URL and deployment URL at the end.

## Follow the instructor's checkpoints

1. **Accounts ready.** Sign into GitHub, Vercel, and the selected AI editor. Complete verification on your own device. Never share passwords or verification codes.
2. **Your copy ready.** Use this repository's template button to create a project in your own account. Do not edit the shared starter.
3. **Site open.** Open your project in the demonstrated AI editor and start its development preview.
4. **First change ready.** Customize the homepage headline and introduction. Change one article if time permits. Review the result.
5. **Saved.** Commit with a message that describes your change.
6. **Deployed.** Import your repository into Vercel and check the build settings in the README.
7. **Verified.** Open the deployment URL, confirm your changes, test links, and check a narrow phone layout.

If setup blocks you, follow with a partner while the instructor helps. Keep your own accounts and credentials separate. A partner's project is not evidence that your own deployment is complete.

## Choose a topic

Use a learning journal about photography, cooking, gardening, music, technology, or another interest. Stick to public sample content. You do not need to build a full business or application today.

## First AI prompt

Replace the bracketed fields before submitting this prompt in the selected editor:

```text
Inspect this existing Astro blog starter before changing it.

My topic is [topic]. My audience is [audience].

Explain briefly which files control the homepage headline and introduction,
site title, and sample articles.

Update the homepage headline and introduction for my topic. Update the
site name, browser title, and description to match. Keep the existing
layout, Astro framework, and deployment setup. Use only fictional or
public sample information. Keep Cosmic Themes attribution and the license.

Do not add dependencies, authentication, payments, databases, API keys,
or external services. Do not deploy, publish, or change permissions.

Summarize the files you changed and tell me how to preview the result.
Run the production build if your environment supports it. If you cannot
run it, say so rather than claiming it passed.
```

A chat assistant may explain or generate code without being able to edit your files. Use the instructor's demonstrated editor workflow. Never paste credentials into a conversation or into the project.

## Optional second prompt

```text
Help me customize one existing sample article for my topic. Keep the
required frontmatter fields, valid author reference, and working image
references. Do not invent factual claims or sources. Explain the change,
then build and preview it if your environment permits.
```

## Checks before sharing

- The headline and introduction match your topic.
- Navigation and the article link work.
- Text stays readable on a narrow screen.
- Generated claims have been checked or removed.
- No credentials, client content, or private information are present.
- Sample authors, privacy policy, branding, and metadata are not mistaken for your own.
- You intend the deployment to be accessible under the project's access settings.

## Stretch exercise

Create a branch, change one headline, open a pull request, test the branch preview if available, then merge after review. Check the production deployment again. This is optional, not a requirement for the first session.

## Instructor timing

| Minutes | Activity |
| --- | --- |
| 0 - 4 | Finished example and tool roles |
| 4 - 15 | Account access and verification |
| 15 - 20 | Own repository copy and topic |
| 20 - 35 | Guided AI customization |
| 35 - 42 | Save and explain the commit |
| 42 - 52 | Vercel import and deployment |
| 52 - 58 | Browser checks and correction |
| 58 - 60 | Save URLs and recap |

Demonstrate one action, pause for everyone to repeat it, then check progress. Keep individual login troubleshooting from stopping the whole group. Rehearse the chosen AI editor and Vercel path before the session; the shared template alone does not verify those integrations.
